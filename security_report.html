0. 今回の診断で発見し、即日修正した脆弱性

修正済み発見時 CRITICAL公開ダッシュボードのJSバンドルに管理者用 API キーが平文で埋め込まれていた
dashboard/src/api/client.ts（修正前: VITE_API_KEY を直接使用）
Vite の VITE_ 接頭辞の環境変数はビルド時に JS バンドルへ平文で埋め込まれ、ブラウザに配信される仕様のため、本番公開中の https://cyberattackinfoapi.vercel.app のバンドルから、/admin/crawl・/admin/dependabot-ops 等の管理系エンドポイントも保護する共有シークレット（API_KEY）を誰でも抽出できる状態だった。実際に本番バンドルを取得し、Render 側 API_KEY とバイト一致することを確認済み。抽出したキーは読み取り系だけでなく管理系エンドポイントの認証にも通る、単一の共有キーであった。
対応（PR #122）: 読み取り専用エンドポイント（KEV/OSV/JVN/crawler-logs）専用の require_public_api_key（管理者用 API_KEY または新設の PUBLIC_API_KEY のいずれかを許可）を導入し、/admin/* は引き続き require_api_key（API_KEY のみ）で保護するよう認証を分離。ダッシュボードの埋め込みキーを VITE_PUBLIC_API_KEY（PUBLIC_API_KEY）に置き換えた。Render の API_KEY をローテーションし、Vercel の VITE_PUBLIC_API_KEY に新しい読み取り専用キーを設定して再デプロイ。新バンドルに管理者用キーが含まれないこと、公開キーは読み取り系のみ通り /admin/* のコードパスでは受理されない設計であることを、実バンドル比較とコードレビューの両方で確認済み（2026-09-04 本番反映確認済み）。
