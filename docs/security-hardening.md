# 本アプリ自身の防御（Issue #406）

本アプリは、全アプリの脆弱性情報・Slack 通知・GitHub トークンを扱うため、それ自身が攻撃対象になる。
この文書は、防御の各項目の**対応状況**（実施／一部／未実施・不要の理由）と、既存の対策との差分を記録する。

## 対応状況

| 項目 | 状況 | 内容・理由 |
|---|---|---|
| 管理 API・認証系のレート制限 | **実施** | `app/core/rate_limit.py`。`/admin/*`・`/auth/*`・OAuth の入口を、クライアントごとに 1 分あたり `RATE_LIMIT_PER_MINUTE`（60）回まで。超えたら 429（`Retry-After` つき） |
| 認証失敗の連続による一時ロック | **実施** | 401・403 が 10 分に `RATE_LIMIT_LOCKOUT_FAILURES`（10）回で、`RATE_LIMIT_LOCKOUT_MINUTES`（15）分、すべて拒否。API キーの総当たりを止める |
| 監査ログ（管理操作・認証・MCP トークン） | **実施** | `app/audit/`。誰が（api-key／session／ユーザー名）・いつ・何を・結果。**IP・ヘッダーの値・クエリ・本文は記録しない**。MCP トークンの発行・失効は、ユーザー名と ID（値は記録しない）。保持 `AUDIT_RETENTION_DAYS`（180）日。`GET /api/audit-logs`（管理者用 API キー） |
| 鍵の更新期限の通知 | **実施** | `API_KEY_EXPIRES_ON`・`GITHUB_TOKEN_EXPIRES_ON`（YYYY-MM-DD）を設定すると、`SECRETS_EXPIRY_NOTICE_DAYS`（14）日前から、毎日、管理者の Slack に通知（更新の手順つき）。形式の誤りは、起動時に失敗させる |
| Webhook URL の更新期限 | **不要** | 登録した Webhook URL は、ユーザー自身が登録・解除する（設定画面）。本アプリが期限を決めるものではない。失効・差し替えは、ユーザー側の操作 |
| `pip --require-hashes`（依存の固定） | **未実施** | 依存の全量を、ハッシュつきでロックする仕組み（`pip-compile --generate-hashes` 等）の導入が要る。Dependabot の更新 PR の運用（ロックの再生成）を含めた設計が先。osv-scanner・pip-audit・Dependabot の cooldown（7日）で、当面の供給網のリスクを下げている。次の改善として起票する |
| Docker イメージのダイジェスト固定 | **未実施** | ベースイメージ（`python:3.13-slim`・`node:24`）を `@sha256:` で固定し、Dependabot（docker）で更新する運用が要る。ARM64 のマルチアーキテクチャのダイジェストの扱いを確認してから。次の改善として起票する |
| DB（Neon）のバックアップと復元テスト | **要確認（あなたの操作）** | Neon は、履歴（Point-in-time restore）を提供する。保持期間はプランによる。**復元テストは、本番を壊さないよう、ブランチ（Neon の branch）へ復元して行う**。手順: Neon コンソール → Branches → 過去の時刻から新しいブランチを作成 → そのブランチの接続文字列で `alembic current` と主要テーブルの件数を確認 → ブランチを削除。結果（所要時間）を、この表に追記する |
| 既存の対策との差分の整理 | **実施** | 下の表 |

## 既存の対策と、今回の追加

| 領域 | 既存 | 今回の追加・差分 |
|---|---|---|
| 認証 | API キーの定数時間比較（`hmac.compare_digest`）・公開用キーと管理者用キーの分離・セッション JWT | 失敗の連続でロック（総当たり対策） |
| MCP | トークン台帳（個別の失効・期限）・OAuth 2.1・本人所有のみ | 発行・失効の監査ログ |
| 入出力 | nosniff 等のセキュリティヘッダー（ZAP 指摘対応）・CSP（ダッシュボード）・`safeHttpUrl` | 変更なし |
| 通知 | 外部由来の文字列は mrkdwn を無害化（`escape_mrkdwn`） | 変更なし |
| 検知 | ruff（bandit 相当）・Semgrep・gitleaks・OSV-Scanner・pip-audit・zizmor・ZAP（月1回） | 変更なし |
| 監視 | Prometheus/Grafana・Slack のエラー通知 | 監査ログ・鍵の期限の通知 |

## 運用上の注意

- **レート制限の状態は、メモリ上**（再起動で消える）。本アプリは 1 コンテナのため、共有の保存先は持たない。
  複数のコンテナにするときは、Redis 等に替える。
- **クライアントの識別**は、Caddy が付ける `X-Forwarded-For` の**最後の値**を使う（先頭の値は、クライアントが
  偽れるため使わない）。Caddy を介さず公開するときは、この前提が崩れるため、見直す。
- 制限・ロックの値を変えるときは、`.env.production` の `RATE_LIMIT_*` を更新して再デプロイする。
  誤って自分がロックされたら、15 分待つか、コンテナを再起動する（状態が消える）。
- 鍵を更新したら、`*_EXPIRES_ON` も、次の期限に更新する（更新しないと、期限切れの通知が続く）。
