# ダッシュボードのタブ組み替えと「概要」タブ 設計書

## 1. 目的（なぜ）
同じ種類の機能が別のタブに散らばり、探しにくい。DEPSCAN は本体のほかに、対応状況（SLA）・Dependabot 運用・
依存の一覧・言語の EOL をモーダルで持ち、見つけにくい。依存ライブラリのアラートは POSTURE にもあり、
コードのアラートは CODESCAN と同じ分野。さらに、全体の状況をすぐ見られる入口がない。

- **ゴール:** (1) 同じ分野の機能を同じタブにまとめ、探しやすくする (2) 開いてすぐ「今、対応が必要なもの」が分かる「概要」を足す
- **非ゴール:** バックエンドの変更。KEV・OSV の機能変更。見た目の全面刷新。新しい集計の追加
- **アンチゴール:** 既存の機能・画面が減ること。0 件と「取得できない」が区別できなくなること

## 2. 新しいタブ構成（6 → 5 タブ）
`概要` / `依存ライブラリ` / `コードと設定` / `運用` / `公開情報`（左から。最初に開くのは概要）

| タブ | 小タブ（中身） | 移す元 |
|---|---|---|
| 概要 | なし（件数のカード） | 新規 |
| 依存ライブラリ | 検知 / 対応状況 / Dependabot運用 / 依存一覧 / EOL / アラート | DEPSCAN 本体、同モーダル4つ、POSTURE のアラート（dependabot種別） |
| コードと設定 | 検知 / アラート / 設定の監査 | CODESCAN、POSTURE のアラート（code・secret種別）・設定の監査 |
| 運用 | 外形監視 | POSTURE の外形監視 |
| 公開情報 | KEV / OSV | 別々の2タブ |

- SLA は依存の検知の期限なので「依存ライブラリ」に置く（「運用」ではない。承認済みの判断）
- 運用中／運用停止中の2区画（#517）は、アラート・設定の監査・外形監視の中身として引き継ぐ

## 3. 作り方（Approaches）
- **A. 小タブで切り替える（採用）:** 各タブの中に小タブを置く。モーダルは小タブの中身になる。探しやすく、1画面が軽い。モーダル4つを画面へ組み直す作業がある
- B. 1枚のページに縦に並べる: 長く重い。スマホで見づらい。不採用
- C. モーダルのまま場所だけ移す: 「探しにくい」が直らない。不採用

## 4. 設計（オブジェクト指向・ハードコード回避）
- **タブ定義の入れ子:** `TabDefinition` に `subTabs?: SubTabDefinition[]` を足す。タブバー・小タブバーは定義から描くだけ。タブ名・並び・アイコン・文言は `tabs.tsx` と設定ファイルの1か所に置く
- **小タブの共通部品:** `SubTabBar`（役割: 小タブの切り替え表示のみ）。選択状態は、タブごとに保持し、タブを離れても戻ると復元
- **モーダル→パネル化:** 既存モーダルの本体を、モーダル枠から切り離して `…Panel` にする。モーダル枠（`Modal`）は外す。中身のロジックは変えない（移動のみ）
- **ログインゲート:** 3つのゲート（DEPSCAN・CODESCAN・POSTURE）を、共通の `GithubLoginGate` に統一済みの部品へ寄せ、新タブ（依存ライブラリ・コードと設定・運用・概要）は同じゲートを使う
- **概要の集計:** 領域ごとの小さなクラス（`OverviewMetric`＝名前・値・状態〈ok/warn/unknown〉・移動先）と、集める役（`OverviewData` フック）に分ける。値の取得元は既存 API:
  - 依存: `fetchDepscanStats`（open_total）、`fetchSlaReport`（overdue）、`fetchRuntimes`（eol・eol_soon の件数）
  - コード: `fetchCodescanStats`（open_total）、`fetchGithubAlerts`（未対応）、`fetchRepoAudit`（達成率）
  - 運用: `fetchSiteMonitor`（指摘のある件数）
  - すべて `operating=active`（運用中のみ）。1つの取得失敗は他に影響せず「不明」と表示
- **移動:** 件数カードを押すと、該当タブ・小タブへ移る（タブ・小タブのキーで指定。文字列の直書きはしない）
- **ハードコード回避:** 件数の色分けの基準・ラベル・移動先は `overviewConfig.ts` に置く
- **URL・復元:** 既存の「ログイン後に DEPSCAN へ戻る」処理は、新しいキー（依存ライブラリ）へ置き換える

## 5. 影響範囲とテスト
- 画面: `tabs.tsx`、`TabBar`・`TabPanel`、`App.tsx`、DEPSCAN/CODESCAN/POSTURE 各パネル、モーダル4つ
- E2E: 最初のタブが KEV であることを前提にしたもの（APP 系など）、DEPSCAN のモーダルを開くもの（DEP-08 ほか）、タブ名で探すもの全般を直す。シナリオ網羅率は100%を維持
- Vitest: タブ定義・小タブ・概要の集計（0件／不明／取得失敗）を追加
- ドキュメント: `dashboard-frontend` スキル、CLAUDE.md（タブ数の記述1行）、README

## 6. 進め方（PR の分け方）
1. 小タブの土台（`SubTabBar`・定義の入れ子）と、公開情報（KEV+OSV）
2. 依存ライブラリ（DEPSCAN＋モーダル4つのパネル化＋アラート）
3. コードと設定・運用（CODESCAN＋POSTURE の分割）
4. 概要
各 PR でテスト・E2E を通し、マージする。途中でも、画面が壊れない状態を保つ

## 7. 未解決・builder の判断に任せる点
